০১কে কী করেন

প্রতিটা ব্যবহারকারী login করলে নিজের panel-এ যান, আর শুধু নিজের কাজের অনুমতি পান।

Super admin/super-admin
  • দাম (rate card) আর নিয়ম ঠিক করা
  • SMS ও email-এর লেখা
  • Merchant অনুমোদন আর KYC
  • Role আর permission
  • Excel template-এর required column
Operations manager/courier-operation
  • সব hub আর rider দেখেন
  • Order confirm, rider assign
  • Linehaul, return, SLA, report
Hub manager/courier-operation · শুধু নিজের hub
  • Parcel scan করে receive
  • নিজের hub-এর rider assign
  • Rider-এর কাছ থেকে নগদ টাকা বুঝে নেওয়া
Rider/rider · phone-এ app
  • Shift শুরু করা (তখনই live location যায়)
  • Pickup আর delivery
  • Proof (code, ছবি বা সই), COD আদায়
  • Hub-এ টাকা জমা
Merchant/ecommerce-merchant · /banking-merchant
  • Order দেওয়া: একটা একটা, Excel বা API
  • Parcel track করা, return চাওয়া
  • Settlement আর invoice দেখা
Customerwebsite
  • নিজের parcel book (login করে বা guest)
  • Tracking, delivery-র পরে rating
Finance/courier-operation → COD & finance
  • একজন settlement তৈরি করেন, আরেকজন অনুমোদন দেন
  • VAT invoice, ব্যাংক বা bKash-এর হিসাব মেলানো
  • Claim বা dispute
Supportসব panel-এর support
  • Ticket-এর উত্তর (প্রতিটার উত্তর দেওয়ার শেষ সময় থাকে)
  • সংরক্ষিত উত্তর ব্যবহার
  • Rider আর franchise-এর আবেদন

০২একবারের setup

কাজ শুরুর আগে একবার করতে হয়। পরে দরকার হলে বদলানো যায়।

  1. Super adminRate card আর দাম, SMS/Email gateway-র key, notification-এর লেখা, Excel template-এর required column।
  2. আগে থেকেই আছে৬৪টা জেলা, ৬০১টা zone আর ৪,৯৩৫টা এলাকা, আর ৩০টা hub। প্রতিটা zone কোনো না কোনো hub-এর আওতায়। কোন hub কোন এলাকায় deliver করবে, তা এখান থেকেই ঠিক হয়।
  3. OperationsRider যোগ করা আর তার hub ঠিক করা। Rider NID আর licence upload করে, Operations যাচাই করে (KYC)।
  4. Merchant → Super adminMerchant আবেদন করে (অথবা invitation পায়)। তারপর trade license, NID আর ব্যাংকের তথ্য দেয়, super admin যাচাই করেন। Merchant হয় ACTIVE।

০৩Order তৈরি: চারটা পথ

যে পথেই আসুক, প্রতিটা order পায় নিজস্ব tracking ID (যেমন PP-261016-B54GG), আর শুরু হয় Pending operations confirmation থেকে।

পথকে করেনকোথায়খেয়াল রাখুন
ক. Merchant নিজেMerchantPanel-এ order form, Excel import, বা APIExcel-এ preview দেখে তারপর তৈরি; ভুল সারি বাদ যায়
খ. Merchant Excel পাঠায়OperationsE-commerce বা Document operations → Import → Rider pickupপ্রতিটা সারিতে merchant-এর নাম বা code লাগবে
গ. Hub-এ সরাসরি জমা (drop-off)Operations বা Hub managerImport → Drop-off at hub + hubUpload-এর পরে label print করে parcel-এ লাগাতে হয়
ঘ. সাধারণ customerCustomerWebsite → Send a parcelGuest হলে ফোনে SMS code দিয়ে যাচাই
Needs info: তথ্য কম থাকলেও order তৈরি হয়, default ধরে charge সহ। কিন্তু প্রাপকের নাম, ফোন, ঠিকানা, জেলা আর zone পূরণ না হওয়া পর্যন্ত delivery rider assign করা যায় না। Merchant বা Operations Complete button দিয়ে পূরণ করেন।
Operations confirm করার আগ পর্যন্ত merchant বা customer নিজে order cancel করতে পারেন। Confirm হওয়ার পরে শুধু Operations পারে।

০৫Parcel hub-এ আনা

Rider pickup

  1. Operations / Hub managerShipments → Accept & assign rider। অনেক order হলে Dispatch → Create dispatch (system rider প্রস্তাব করে), অথবা Excel bulk update। Status: Pickup assigned
  2. RiderApp-এ pickup দেখে, merchant-এর কাছে গিয়ে parcel নেয়। Status: Picked up
  3. RiderParcel hub-এ নিয়ে আসে।
  4. Hub managerHub console-এ scan করেন। Status: At hub

Hub-এ drop-off

  1. OperationsExcel import → Drop-off at hub। Tracking-এ দেখায় "Awaiting drop-off at …"। কোনো rider লাগে না।
  2. OperationsPrint labels: A4 sheet-এ ৪টা, অথবা 100×150 mm thermal। Barcode, প্রাপক আর COD-এর পরিমাণ বড় করে লেখা থাকে।
  3. Hub-এর কর্মীপ্রতিটা parcel-এ label লাগান।
  4. Hub managerHubs → receive desk-এ scanner, camera বা টাইপ করে receive। "আসার কথা / এসেছে / বাকি" দেখা যায়। Status: At hub
Pickup হওয়ার আগে পর্যন্ত Operations order-কে Change to drop-off বা Change to rider pickup করতে পারে। দাম নতুন করে হিসাব হয়, আর sender SMS পায়।

০৬এক hub থেকে আরেক hub (linehaul)

System প্রাপকের zone দেখে ঠিক করে কোন hub deliver করবে। প্রথম hub আর সেই hub এক না হলে parcel গাড়িতে যায়, যেমন Gulshan থেকে Chattogram।

  B1 --> S[Bag seal]
  S --> TR[Trip: গাড়ি, manifest, bag load]

  1. Hub manager · প্রথম hubCourier Operations → Linehaul-এ bag তৈরি করে parcel scan করে ঢোকান, তারপর seal করেন।
  2. Hub managerTrip তৈরি করে গাড়ি বাছেন, manifest print করেন, bag load করেন। গাড়ি ছাড়লে সব parcel হয় In transit।
  3. Hub manager · গন্তব্যের hubBag scan করে receive করেন। কোনো parcel কম বা বেশি থাকলে system নিজেই discrepancy হিসেবে চিহ্নিত করে।

০৭Delivery

  1. Operations / Hub managerDispatch: map, route planner আর rider-এর প্রস্তাব দেখে delivery rider assign। Status: Assigned
  2. RiderApp-এ delivery শুরু করে। প্রাপক SMS-এ delivery code পান। Status: Out for delivery
  3. Riderপ্রাপকের code দেয়, অথবা ছবি বা সই নেয়। Proof-এ সময় আর location-এর ছাপ পড়ে। COD থাকলে টাকা নেয়। Status: Delivered
  4. Rider · না পারলেকারণ লিখে Retry scheduled, পরের দিন আবার চেষ্টা।
Delivered শুধু rider-ই করতে পারে, proof দিয়ে। Operations বা Excel থেকে Delivered করা যায় না, যাতে প্রমাণ আর COD ছাড়া কোনো parcel "delivered" না হয়। Internet না থাকলেও rider কাজ চালিয়ে যেতে পারে; network এলে সব sync হয়।

০৮Return (RTO)

  1. Operationsবারবার ব্যর্থ হলে, অথবা merchant return চাইলে, status দেন Return scheduled। Return charge হিসাব হয় rate card অনুযায়ী।
  2. OperationsReturns (RTO) page-এ return run তৈরি করে rider দেন।
  3. RiderParcel merchant-কে ফেরত দেয়। Status: Returned
  4. MerchantPanel-এ "received" নিশ্চিত করে। Return charge invoice-এ বা পরের settlement-এ যোগ হয়।

০৯টাকার পথ: COD থেকে merchant-এর হাতে

sequenceDiagram
  participant R as Rider
  participant H as Hub manager
  participant F1 as Finance (তৈরিকারী)
  participant F2 as Finance (অনুমোদনকারী)
  participant M as Merchant
  R->>H: Cash handover request + নগদ টাকা
  H->>H: COD & finance → Receive
  F1->>F1: Draft settlement (COD − charge ± adjustment)
  F1->>F2: অনুমোদনের জন্য
  F2->>F2: Approve (অন্য একজনকেই করতে হয়)
  F1->>M: bKash বা ব্যাংকে টাকা, reference দিয়ে Mark paid
  M-->>M: SMS আর panel-এ settlement দেখা
  1. Riderদিনের শেষে app-এ Request cash handover দেয়, তারপর hub-এর cashier-কে টাকা দেয়।
  2. Hub managerCOD & finance → Cash handover requests → Receive। টাকার হিসাব rider-এর ঘর থেকে hub-এর ঘরে চলে যায়।
  3. Finance (তৈরিকারী)Draft settlement। দৈনিক বা সাপ্তাহিক নিয়ম ঠিক করা থাকলে system নিজেই draft তৈরি করে।
  4. Finance (অনুমোদনকারী)Approve। যিনি তৈরি করেছেন, তিনি নিজে অনুমোদন দিতে পারেন না।
  5. Financeটাকা পাঠিয়ে transaction reference দিয়ে Mark paid। Merchant SMS পায়।
পাওনা ঋণাত্মক হলে (charge বেশি, COD কম) টাকা যায় না; ঘাটতি পরের settlement থেকে কাটা হয়। হিসাবের entry বদলানো বা মোছা যায় না, ভুল হলে উল্টো একটা entry দিয়ে ঠিক করতে হয়।

Excel-এ district বাছলে zone-এর dropdown শুধু সেই district-এর zone দেখায়। এটা Microsoft Excel আর LibreOffice-এ কাজ করে, Google Sheets-এ করে না। Download করার পরে কেউ parcel বদলে থাকলে সেই সারি আটকে যায়, যাতে পুরনো তথ্যের উপর কাজ না হয়।

১১পুরো সময় যা চলতে থাকে

SLAপ্রতিটা parcel-এর pickup আর delivery-র শেষ সময় থাকে। দেরির ঝুঁকি হলে At risk, দেরি হয়ে গেলে Breached, আর manager email পান।
Live trackingMerchant আর customer প্রতিটা ধাপ সাথে সাথে দেখেন। প্রধান ধাপে SMS যায়।
Rider-এর locationশুধু shift চালু থাকলে, app খোলা থাকলে আর browser location-এর অনুমতি দিলে Operations-এর map-এ দেখা যায়।
SupportTicket-এর উত্তর দেওয়ার শেষ সময় থাকে, দেরি হলে ticket উপরের স্তরে যায়। সমাধান হলে customer ১ থেকে ৫ rating দেন।
Auditকে, কখন, কী বদলেছেন, সব লেখা থাকে। Bulk কাজের প্রতিটা সারিতে তার নম্বর থাকে।

১৩প্রতিদিনের চেকলিস্ট
